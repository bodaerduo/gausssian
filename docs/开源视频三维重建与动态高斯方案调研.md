# 开源视频三维重建与动态 Gaussian 方案调研

> 调研日期：2026-09-02  
> 对照对象：本项目当前的 `FFmpeg → COLMAP → Brush → final.ply`   
> 目标：找到可自托管的开源视频建模方案，并重点评估“逐步重建、实时看到模型长出来、对动态内容更友好”的路线。

## 1. 结论先行

1. **当前 COLMAP + Brush 仍适合作为最终交付主线。** 它的中间产物明确、PLY 兼容性好、质量容易复核；代价是相机位姿和稀疏点要等 COLMAP 完成，用户看不到真正的流式建模过程。
2. **LingBot-Map 最适合做流式预览前端。** 官方实现从普通 RGB 视频连续预测相机、稠密点图和轨迹，约 20 FPS（518×378），可处理超过 10,000 帧；还提供 Viser 交互查看器和离线点云飞行渲染。它输出的是点云/位姿，不是训练好的 3DGS PLY，因此需要适配层才能接 Brush/gsplat。
3. **高德 AMAP 的 ABot-Recon 是更轻量的长视频流式候选。** 它固定使用 12 帧局部上下文，逐帧组合相对位姿和点图；官方报告 KITTI-02 上 24.45 FPS（H100，504×280），默认最长 22,000 帧，并支持可选回环优化。它同样输出轨迹、局部/全局点云和置信度，而非 Gaussian 参数。
4. **如果“动态”指物体真的在运动，需单独评估 4D/可变形 Gaussian。** 4DGaussians、Fudan 4D Gaussian Splatting、Deformable 3D Gaussians 等能表示时间变化，但多数仓库面向论文数据集或已知相机，不是即插即用的“任意手机视频 → 动态 PLY”。
5. **推荐混合架构：流式预览与最终训练分离。** 上传后先抽低帧率，LingBot-Map/ABot-Recon 每个窗口持续产出点云预览并通过 SSE 推送；视频结束后再用同一批帧走 COLMAP + Brush 生成高质量 `final.ply`。这样既能“慢慢建模”，又不牺牲最终质量和现有验收标准。

## 2. 先区分三类“视频建模”

| 类型 | 代表方案 | 主要输出 | 是否直接得到 3DGS | 适合本项目的角色 |
|---|---|---|---|---|
| 静态离线摄影测量 + 3DGS | COLMAP + Brush、Nerfstudio Splatfacto | 相机位姿、稀疏点、Gaussian PLY | 是 | 最终高质量交付 |
| 流式几何重建/SLAM | LingBot-Map、ABot-Recon、VGGT、MASt3R-SLAM | 相机轨迹、深度/点图、点云 | 否（通常需适配） | 实时预览、质量早检、长视频 |
| 动态/4D 表示 | 4DGaussians、Deformable 3D Gaussians、SC-GS | 随时间变化的 Gaussian/形变场 | 是（但格式和训练流程各自不同） | 动态人物、运动物体、时间插值 |

“逐步看到模型长出来”不一定等于“动态 4D”。对静态场景，它通常是**流式点云预览 + 最终 Gaussian 训练**；对运动场景，才需要显式的时间维度和形变模型。

## 3. 方案横向对比

| 方案 | 输入与流程 | 渐进可视化 | 动态能力 | 与当前工程的衔接 | 主要优点 | 主要限制 |
|---|---|---|---|---|---|---|
| **当前：COLMAP + Brush** | 视频抽帧 → SIFT/匹配/Mapper → Brush 训练 | 弱；可展示阶段进度，不能稳定展示半成品 Gaussian | 静态假设；运动会重影 | 已集成，直接产 `final.ply` | 结果成熟、格式通用、可复现 | COLMAP 较慢；前期失败反馈晚 |
| **Nerfstudio Splatfacto + gsplat** | `ns-process-data`/COLMAP → `ns-train splatfacto` | 强；自带 Web viewer，可加载 checkpoint、渲染和导出 PLY | 主要是静态；动态需额外方法 | 可替换 Brush，或作为实验分支 | Python API、参数多、调试和 viewer 友好；Apache-2.0 | CUDA/PyTorch 环境复杂；训练仍是离线优化 |
| **LingBot-Map** | RGB 视频/帧 → feed-forward GCT → 相机、点图、轨迹 | **强**；Viser 实时查看，支持长视频离线点云飞行 MP4 | 可处理动态序列的几何变化，但不是时间 Gaussian | 作为 preview worker；结束后把轨迹/点云转 COLMAP 或独立训练输入 | 约 20 FPS、长序列、Apache-2.0、带 windowed inference 和 sky mask | 需要约定 CUDA 12.8/PyTorch 2.8；模型权重体积大；输出不是 3DGS |
| **ABot-Recon（AMAP）** | 帧序列 → 固定 12 帧局部上下文 → 相对位姿累积 + 点图 | **强**；逐帧保存局部点图、置信度和轨迹，可导出 PLY/BEV | 对长时程和局部动态更稳，但仍主要是几何流 | 作为 preview/pose front-end；需写 PLY/COLMAP adapter | Apache-2.0 代码；24.45 FPS（H100）；可选回环；最长 22k 帧 | 当前发布环境偏 Linux + CUDA；模型权重另有 MODEL_LICENSE；训练代码尚未完全发布 |
| **VGGT** | 多张图/视频 → 一次或分块前向 → 相机、深度、点图、轨迹 | 中到强；官方 viser demo，结果可保存为 COLMAP 格式 | 非专门动态模型 | 可替代 COLMAP 做快速初始位姿，但需质量验证 | 无需传统 SfM 迭代，适合快速预览/初始化 | 长视频需分块；模型/权重许可要单独审计；不是 3DGS 训练器 |
| **MASt3R-SLAM** | MP4/图像目录/RealSense → 实时稠密 SLAM | **强**；定位和稠密地图同步更新 | 主要针对相机运动，动态物体会影响地图 | 可做实时地图预览或采集质量监控 | 明确支持视频和实时相机，适合“边拍边看” | 依赖 MASt3R 权重及 CUDA；研究型工程，稳定性和许可需逐项核实 |
| **4DGaussians（HUST）** | 论文数据集/预处理 → 时间相关 Gaussian 训练 | 训练后可实时渲染动态新视角 | **强**，显式时间维度 | 不能直接替换现有静态 Brush；需新数据契约 | CVPR 2024、Apache-2.0；动态视角/自由视角 demo | 典型流程依赖 COLMAP 稠密点和数据集格式；不保证任意单目视频即用 |
| **Fudan 4D Gaussian Splatting** | D-NeRF/Neural 3D Video 等数据集 → 4D primitive 训练 | 强；仓库提供 dynamic novel-view、bullet-time、monocular demo | **强** | 作为独立动态实验线 | MIT；原生 4D primitive，实时渲染 | 环境较老、数据准备重；与生产 API/PLY 契约不同 |
| **Deformable 3D Gaussians** | 单目动态视频/NeRF-DS/HyperNeRF → canonical Gaussian + deformation field | 训练后实时 viewer | **强**；适合单目动态场景和时间插值 | 需单独 worker 和数据转换 | MIT；有 Lightweight 版本和实时 viewer | 官方环境偏 Python 3.7/PyTorch 1.13/CUDA 11.6，维护成本高 |
| **OOOSplat** | 桌面端视频 → FFmpeg → COLMAP → Brush → PLY | **强**；阶段、计数器、日志、预览和动画导出 | 静态为主 | 可作为产品交互参考，非后端依赖 | Apache-2.0 一方代码；实时日志/预览体验完整 | 桌面应用而非服务端；第三方引擎仍按各自许可证；当前动态能力有限 |

## 4. 重点方案说明

### 4.1 LingBot-Map：最适合“长视频逐步长地图”

官方仓库将它定义为基于 Geometric Context Transformer 的流式 3D 重建模型。核心状态由 anchor context、pose-reference window 和 trajectory memory 组成，并使用 paged KV cache；README 报告在 518×378 输入上约 20 FPS、超过 10,000 帧仍可稳定推理。仓库还提供：

- `demo.py`：交互式 Viser 点云/轨迹查看；
- `--mode windowed`：超长序列滑窗推理；
- `--mask_sky`：户外天空点过滤；
- `demo_render/batch_demo.py`：输出点云飞行 MP4、原始 RGB MP4 和运行配置；
- 动态序列 demo（Droid-W）以及约 25,000 帧、13 分钟室内 walkthrough 示例。

它的输出本质是相机参数和 RGB 点云/深度，不是 Brush 所需的完整 Gaussian 属性（尺度、旋转、不透明度、球谐颜色等）。因此更合理的集成方式是：

```text
视频 → LingBot-Map（实时点云预览 + 轨迹）
     ├─ SSE：每 N 帧发布 preview.ply / 相机轨迹 / 置信度
     └─ 任务结束：原帧 → COLMAP + Brush → final.ply
```

若要用 LingBot-Map 加速最终训练，需要实现“点图/位姿 → COLMAP sparse 或 transforms.json”的转换，并用 A/B 测试确认是否损失静态场景质量。

### 4.2 ABot-Recon：更适合受控的流式前端

ABot-Recon（仓库名 `amap-cvlab/ABot-Recon`）选择严格局部策略：缓存此前 11 帧，在当前相机坐标系预测点图，估计相邻帧相对位姿，再逐步组合为全局轨迹和点云。官方 README 给出的结果包括：

- Oxford Spires：ATE 4.35 m、旋转 RPE 0.12°；
- KITTI-02：24.45 FPS、6.71 GiB（H100，504×280）；
- 默认支持最多 22,000 帧；
- 可选 DINOv2-SALAD 回环检索和稀疏位姿图优化；
- 可保存 `local_points.pt`、`world_points.pt`、`confidence.pt`、轨迹 `.npy`，并导出 RGB 点云 PLY 和 BEV 轨迹图。

优点是状态和单帧计算量不随历史长度增长，适合在后端任务中按窗口产出中间结果。注意：源代码为 Apache-2.0，但**模型权重使用单独的 `MODEL_LICENSE.md`**，不能只看代码许可证就直接做商业分发；官方发布配置面向 Linux/PyTorch 2.5.1/CUDA 12.1，且训练代码仍标记为后续发布计划。

### 4.3 4D/可变形 Gaussian：真正的动态，但不是简单升级

- **4DGaussians（HUST，Apache-2.0）**：将空间和时间联合建模，仓库有动态新视角和自由视角示例，但数据准备通常依赖已整理的数据集和 COLMAP 稠密点。
- **Fudan 4D Gaussian Splatting（MIT）**：原生 4D primitive，仓库展示 dynamic novel view、bullet-time、teleporting camera 和 monocular dynamic demo；更偏论文复现环境。
- **Deformable 3D Gaussians（MIT）**：在 canonical space 训练 Gaussian，再用 deformation field 表示时间变化；适合单目动态研究，但官方依赖版本较老。

这些方案的共同限制是：动态目标、相机运动、遮挡和拓扑变化需要同时估计；单个手机视频未必提供足够视角，人物/反光/透明物体仍会出现漂移和重影。建议先把它们作为独立实验 worker，不要直接替换现有静态生产链。

## 5. 针对本项目的推荐架构

### 推荐：双轨流水线

```text
上传视频
   │
   ├─ 快速预览轨（每 2～5 帧取一帧）
   │    └─ LingBot-Map 或 ABot-Recon
   │         ├─ 相机轨迹
   │         ├─ 置信度/深度
   │         ├─ 增量点云 preview-N.ply
   │         └─ SSE 推送：frame、registered、point_count、preview_url
   │
   └─ 最终质量轨（视频结束或用户点击“精修”）
        └─ FFmpeg → COLMAP → Brush → PLY 校验 → final.ply
```

### 后端改造建议（不改变现有完成判定）

1. 新增状态 `previewing`，不改变现有 `extracting → reconstructing → training → exporting` 主链。
2. 预览 worker 每累计 32～128 帧写一个带序号的 `preview/points-0001.ply`，并在 SSE 发送 URL、点数、置信度均值和当前帧号。
3. 前端用同一个 WebGL 点云查看器替换模型数据，增量加载新 PLY；用户能看到点云从稀疏到稠密变化。
4. 预览失败时只记录 warning，必须允许任务继续进入现有 COLMAP + Brush；不能用学习式预览结果直接判定 `completed`。
5. 对静态场景，先比较三种初始化：COLMAP sparse、LingBot world points、ABot world points。指标至少记录注册率、有效点数、最终 PLY 大小、渲染 PSNR/SSIM（若有 GT）和人工缺陷评分。
6. 动态实验单独使用 `dynamic=true` 数据契约，输出按时间索引的 checkpoint/PLY 或 4D 专用格式，避免把动态模型误标成静态 `final.ply`。

### 预览质量门槛

- 点数持续增长且相邻窗口没有明显跳变；
- 相机轨迹无突然翻转、尺度突变；
- 置信度低的点使用阈值过滤；
- 室外场景默认开启天空 mask；
- 预览只做“可视化和早期质量反馈”，不替代最终 PLY 的位置、颜色、透明度、尺度、旋转和顶点数校验。

## 6. 选择建议

| 你的优先级 | 首选 | 说明 |
|---|---|---|
| 最终质量和现有代码改动最少 | COLMAP + Brush | 保持生产主线 |
| 看着模型逐步出现 | LingBot-Map | 长序列 demo 和离线点云渲染最完整 |
| 更轻量的流式预览/轨迹 | ABot-Recon | 固定局部上下文、输出置信度、支持回环 |
| 想用纯 Python viewer 和 checkpoint | Nerfstudio Splatfacto | 可替换 Brush 做实验和调参 |
| 需要实时相机定位/稠密地图 | MASt3R-SLAM | 更像 SLAM 前端，不是 Gaussian 训练器 |
| 真的要建模运动人物/物体 | Deformable 3D Gaussians 或 4DGaussians | 另建动态实验线，先接受更高部署复杂度 |
| 想参考完整交互产品体验 | OOOSplat | 借鉴阶段日志、预览、动画和任务历史设计 |

**我的推荐顺序：**先接入 LingBot-Map 做只读预览；如果显存/部署约束更适合局部模型，再评估 ABot-Recon；最终训练继续使用当前 Brush。等静态双轨流程稳定后，再用一个短动态样片单独验证 Deformable 3D Gaussians 或 4DGaussians。

## 7. 许可证与供应链注意事项

- LingBot-Map：仓库标注 Apache-2.0；模型权重仍应按下载页/权重文件单独审计。
- ABot-Recon：源代码 Apache-2.0，模型权重遵循仓库中的 `MODEL_LICENSE.md`，第三方组件见 `THIRD_PARTY_NOTICES.md`。
- Nerfstudio：Apache-2.0；gsplat 和 PyTorch/CUDA 依赖需分别记录版本。
- 4DGaussians（HUST）：仓库标注 Apache-2.0；Fudan 4DGS 标注 MIT；Deformable 3D Gaussians 标注 MIT。
- OOOSplat：一方代码 Apache-2.0，但 FFmpeg、COLMAP、Brush、PlayCanvas、Mediabunny 仍按各自许可证执行。
- 输入视频的人像、建筑、室内物品、音乐和纹理版权不因使用开源模型而自动获得许可；发布前要单独确认隐私和版权边界。

## 9. 平台产品路线扩展（不替换 Brush）

本节是产品化边界：ABot-Recon 和 LingBot-Map 是新增的实验/预览路线，现有 `FFmpeg → COLMAP → Brush → final.ply` 仍是默认生产路线；SuperSplat 继续只处理已生成的 Gaussian PLY。

### 产品入口

建议在“新建重建”旁新增“产品路线”选择，不改变原有默认值：

| 路线 ID | 产品名称 | 主要体验 | 输出资产 | 当前定位 |
|---|---|---|---|---|
| `brush_static` | 标准 Gaussian 建模 | 上传后等待完整重建，得到可编辑 Gaussian PLY | `final.ply` | 默认、稳定交付 |
| `abot_recon_poc` | ABot-Recon 流式扫描（POC） | 点云逐窗口出现、相机轨迹和置信度实时变化 | `preview/*.ply`、轨迹、点图；可选最终 PLY | 新增实验路线 |
| `lingbot_map` | LingBot-Map 空间地图 | 轨迹线、稠密点云、鸟瞰/跟随镜头、长视频扫描 | 点云预览、轨迹、渲染 MP4；可选最终 PLY | 新增展示路线 |

### 两个新增产品的特色功能

#### ABot-Recon POC：可控、轻量、适合服务化

- 固定 12 帧局部上下文，按帧组合相对位姿和点图，适合把视频拆成小窗口持续处理；
- 输出 `camera_poses`、`relative_poses`、`local_points`、`world_points`、`confidence`，便于前端显示“当前扫描进度”和低置信度区域；
- 可选回环优化，用户绕回原位置时可修正轨迹漂移；
- 适合做后端 Worker + SSE 的第一个 POC：每 32～64 帧落盘一个普通 RGB 点云预览；
- 不直接输出 Gaussian 属性，预览用普通点云 Viewer；任务完成后是否进入 Brush 由路线配置决定。

#### LingBot-Map：更强的展示感和长视频能力

- Geometric Context Transformer + paged KV cache，面向长视频流式重建；
- 官方提供浏览器 Viser Viewer，可显示点云、轨迹和当前相机；
- 支持 `windowed` 长序列推理、天空遮罩、动态序列 Demo；
- 提供跟随镜头、鸟瞰镜头、静态镜头和点云飞行 MP4，适合做产品宣传或大屏展示；
- 适合独立 GPU 服务运行，不建议第一版直接嵌入主 API 进程；
- 输出仍是点云/位姿，不能直接交给 SuperSplat 做 Gaussian 编辑。

### 隔离后的任务契约

现有接口继续兼容：

```text
POST /api/v1/reconstructions
  route=brush_static（默认）
```

新增路线可以使用同一任务 ID，但必须保存 `route` 字段并隔离产物目录：

```text
<job_id>/
├── source/                 # 原视频
├── dataset/                # 仅 brush_static 使用
├── output/final.ply        # 仅 Brush 生成，保持原校验
├── preview/                # ABot/LingBot 增量预览
│   ├── points-0001.ply
│   ├── points-0002.ply
│   └── trajectory.json
└── products/
    ├── abot-recon/         # 模型输出和日志
    └── lingbot-map/        # 模型输出、MP4 和配置
```

事件增加产品字段，但保留原有字段：

```json
{
  "type": "preview",
  "route": "abot_recon_poc",
  "frame": 128,
  "point_count": 184320,
  "confidence": 0.82,
  "preview_url": "/api/v1/reconstructions/gs-.../preview/points-0004.ply"
}
```

硬性隔离规则：

1. `brush_static` 的完成判定、`output/final.ply`、SuperSplat 编辑和版本接口保持不变。
2. ABot/LingBot 预览失败只标记该产品路线失败，不删除原始视频，不污染 Brush 任务状态。
3. 普通点云 PLY 不进入当前 Gaussian Viewer；前端必须根据 `asset_type` 选择点云 Viewer 或 Gaussian Viewer。
4. ABot/LingBot 产生的点云只能标记为 `preview`，不能直接标记为可编辑 Gaussian 资产。
5. 模型权重、CUDA/PyTorch 环境和许可证记录在产品路线配置中，不写入现有 Brush 镜像的必需依赖。

### 建议的产品页面

可以新增一个“实验室路线”页面，和“区域场景 / SuperSplat”并列：

- **ABot-Recon POC**：显示“逐帧扫描、置信度、回环优化、普通点云”；按钮为“开始 POC”；
- **LingBot-Map**：显示“长视频地图、轨迹、鸟瞰回放、动态序列”；按钮为“打开地图 Demo”；
- **标准 Gaussian**：继续进入现有上传和 Brush 流程；
- 完成后在同一任务详情中显示“预览资产”和“最终 Gaussian 资产”两个分组，SuperSplat 只出现在后者。

这样平台增加的是三种产品体验，而不是替换一条底层管线：标准路线保证交付，ABot-Recon 提供低风险实时 POC，LingBot-Map 提供高展示性的空间扫描体验。

### 给非技术用户的理解方式

三条路线的关键差别，不是“谁的模型更大”，而是**什么时候让用户看到结果**：

```text
标准 Gaussian：视频结束 → 抽帧/定位 → 训练 → 最终可编辑模型
ABot-Recon：   视频播放中 → 最近 12 帧推理 → 点云和轨迹连续出现
LingBot-Map：  相机移动中 → 地图持续扩张 → 可跟随/鸟瞰/回放
```

ABot-Recon 和 LingBot-Map 的“实时”指流式推理和增量预览：系统不需要等完整视频上传后，再针对这段视频从头训练一个新网络。它们会边接收视频帧、边预测相机和几何结果；因此用户能看到扫描过程，但结果首先是普通点云、点图和轨迹。最终若需要进入 SuperSplat 编辑，仍要把素材交给 Brush 生成并校验 Gaussian PLY。

| 路线 | 普通人看到的过程 | 主要优势 | 主要限制 | 最适合 |
|---|---|---|---|---|
| 标准 Gaussian | 等待完整处理后，看到较完整的高质量模型；完成后可自由漫游和编辑 | 交付稳定、可编辑、可进入 SuperSplat，最终漫游质量最好 | 首屏慢；无法体现“边拍边看” | 最终资产、交付、精修 |
| ABot-Recon | 视频播放时，点云按小窗口一段段出现，轨迹跟着相机走 | 最快接入实时视频；显存和状态较可控；有置信度可筛选 | 轨迹长距离累积可能漂移；不是 Gaussian 输出 | 实时扫描 POC、现场预览、快速反馈 |
| LingBot-Map | 场景像地图一样向前铺开，可切换跟随、鸟瞰和飞行镜头 | “过程展示感”最强：相机路线、地图扩张、扫描进度同时可见 | 依赖和显存更重；部署、渲染和运维成本高；不是最终 Gaussian 资产 | 大屏展示、空间地图、产品演示 |

### 三条链路如何共存

同一段视频可以形成两个阶段的体验：先用 ABot-Recon 或 LingBot-Map 在播放过程中给出“正在扫描”的即时反馈；用户确认素材和覆盖范围后，再选择标准 Gaussian 路线做最终训练。这样实时预览解决等待焦虑，Brush + SuperSplat 负责最终可编辑交付，两者不是互相替代。

这里的“LingBot-Map 展示感”不是说它生成的模型一定比 Brush 最终模型更精细，也不是说标准 Gaussian 不能漫游。它强调的是**把建图过程变成画面**：视频还在播放时，当前相机位置、已经覆盖的区域、不断增长的点云和可切换的鸟瞰/跟随镜头同时呈现。标准路线更像“等成品出来后看成品”；LingBot-Map 更像“看着地图现场长出来”。

产品页面上的选择建议可以简单记成：

- **要交付**：标准 Gaussian；
- **要最快看到模型长出来**：ABot-Recon；
- **要最酷的空间展示**：LingBot-Map。

## 10. Worker 依赖隔离分析与部署建议

### 10.1 结论

两个模型 Worker 不建议直接 `pip install` 到现有 Gaussian API/Brush 容器，也不建议把它们塞进同一个 Python 虚拟环境。第一阶段采用“主应用 + 两个可选 GPU Worker 容器”的结构最稳妥：主应用只负责上传、任务编排、SSE 和资产索引；ABot-Recon、LingBot-Map 通过共享任务目录或内部 HTTP/队列消费视频帧，完成后写回 `preview/` 和 `products/<route>/`。

这不是因为两个模型不能在同一台机器运行，而是它们的 Python/CUDA 依赖节奏不同：隔离可以避免一次实验升级破坏 Brush 生产链，也方便单独回滚模型权重和镜像。

| 组件 | 官方运行约束 | 与当前主应用的关系 | 风险判断 |
|---|---|---|---|
| 现有 Brush + COLMAP | 当前镜像 CUDA 12.4；Brush 是 Rust/WebGPU 二进制；后端仅需要 FastAPI/FFmpeg | 生产默认链 | 保持不动 |
| ABot-Recon | Python ≥3.10、PyTorch 2.5.1、torchvision 0.20.1，发布配置面向 CUDA 12.1；可选 FlashInfer/cuRoPE；回环额外引入 faiss/opencv/pypose/scipy | 与主 API 的 Python 包版本容易产生约束；模型权重另有许可证 | 独立容器，先关闭回环做 POC |
| LingBot-Map | Python 3.10；推荐 PyTorch 2.8.0 + CUDA 12.8；FlashInfer；Viser/Trimesh/ONNX Runtime 为可选展示依赖；批量渲染推荐 Kaolin | 与 ABot-Recon 和主应用都存在 PyTorch/CUDA 版本差异；Kaolin 编译/轮子进一步放大镜像体积 | 独立容器，展示模式和离线渲染分开 |

### 10.2 是否可以放在一起

- **同一台物理 GPU 主机：可以。** Docker 容器共享 NVIDIA 驱动，不等于共享 Python 依赖；只要宿主机驱动满足两个镜像要求，就能按队列串行或按 GPU 切分运行。
- **同一 Docker 容器：不建议。** ABot-Recon 锁定 torch 2.5.1/cu121，而 LingBot-Map 的推荐组合是 torch 2.8.0/cu128；强行合并会遇到 torch、torchvision、FlashInfer、Kaolin 和 ONNX Runtime 的 ABI/编译缓存问题。
- **同一 Python venv/conda 环境：不建议。** 即便当前能 import，后续升级任意一个模型都可能改变 CUDA 扩展或 torchvision 依赖，导致主 API 启动失败。
- **同一 GPU 并发：首版不建议。** 两个模型都吃显存，且 LingBot-Map 的 Viser/离线渲染会额外占用显存；先用 `GAUSSIAN_MAX_WORKERS=1` 和产品级队列串行，稳定后再按 `CUDA_VISIBLE_DEVICES` 做分配。

### 10.3 推荐的三层部署

```text
gaussian-app（现有容器）
  ├─ Brush/COLMAP 生产任务：output/final.ply → SuperSplat
  ├─ abot-worker（可选，torch 2.5.1/cu121）：preview/*.ply + trajectory.json
  └─ lingbot-worker（可选，torch 2.8/cu128）：点云/轨迹 + Viser/MP4
```

第一阶段可以只启动 `gaussian-app`，ABot/LingBot 的开关保持关闭；启用 POC 时再启动 `abot-worker`，不需要重建主镜像。LingBot-Map 的“最酷展示”建议再拆出 `lingbot-renderer`（离线 MP4/鸟瞰回放），避免交互预览服务被批量渲染拖慢。

### 10.4 进程与资产边界

建议通过环境变量配置 Worker 地址和能力，而不是在主 API 中 import 模型：

```text
ABOT_RECON_ENABLED=false
ABOT_RECON_URL=http://abot-worker:8091
ABOT_RECON_CMD="python /opt/abot-worker/run.py --source {source} --output {preview} --quality {quality}"
LINGBOT_MAP_ENABLED=false
LINGBOT_MAP_URL=http://lingbot-worker:8092
LINGBOT_MAP_CMD="python /opt/lingbot-worker/run.py --source {source} --output {preview} --quality {quality}"
```

`*_CMD` 是主 API 的最小 POC 适配方式，花括号会替换为 `job_id`、源路径、`preview` 目录、`products/<route>` 输出目录和质量档位；正式部署可将它替换为调用容器 HTTP API 的 wrapper。每个 Worker 只接收 `job_id`、源视频/帧目录、质量档位和输出目录；主 API 只消费结构化事件：`progress`、`frame`、`point_count`、`confidence`、`preview_url`、`error`。这样即使某个模型容器 OOM 或权重下载失败，也只会让对应产品路线失败，不会改变 Brush 任务的完成判定。

### 10.5 资源与上线顺序

1. **先 ABot-Recon：**基础推理、不装 loop extra，验证视频抽帧、12 帧窗口、点云增量、SSE 和普通点云 Viewer；它的官方基准在 H100 504×280 为 24.45 FPS、约 6.71 GiB，适合做第一条独立 Worker。
2. **再 LingBot-Map：**先跑 `demo.py`/Viser 交互预览，再接 windowed 长视频；天空遮罩和离线 Kaolin 渲染作为可选能力，不放进主 API 镜像。
3. **最后做并发：**观察显存峰值、队列等待和首帧延迟，再决定单卡串行、同机多卡，或为展示环境单独配 GPU 节点。

### 10.6 许可证与供应链

源码均可按仓库许可证审计，但模型权重、FlashInfer、Kaolin、ONNX Runtime 和回环检索模型都应在各自镜像的 SBOM/NOTICE 中登记。ABot-Recon 明确要求单独查看 `MODEL_LICENSE.md`；LingBot-Map 的 Apache-2.0 代码也不自动覆盖模型权重和第三方组件。
